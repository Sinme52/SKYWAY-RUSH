# 引き継ぎ：SKYWAY RUSH のショート動画を作る

このファイルは、ローカルの Claude Code に渡す作業指示です。前のセッションの会話は引き継がれないので、必要なことはすべてここに書いてあります。

## ゴール

ブラウザゲーム「SKYWAY RUSH」のプレイ映像で、YouTube ショート用の縦動画を 1 本作る。

- 出力：`video/out/skyway_short.mp4`
  - 1080×1920（9:16）、30fps 以上、H.264 + AAC、長さ 35〜45 秒（60 秒以内）
- あわせて作るもの
  - サムネイル用の静止画 `video/out/thumbnail.png`（1080×1920）
  - タイトル・概要欄・ハッシュタグの案 `video/out/description.md`
- 動画のテーマ：「画像の拡大縮小と回転だけで作った 3D レースゲーム。絵は GPT Image、プログラムは Claude」

## リポジトリと起動方法

- リポジトリ：`Sinme52/SKYWAY-RUSH`（ゲームはリポジトリの直下にある）。GitHub Pages で公開している：https://sinme52.github.io/SKYWAY-RUSH/
- 作業は、`main` から切った新しいブランチで行う。push は、ユーザーに頼まれたときだけ行う
- 起動：リポジトリの直下で `python3 -m http.server 8000` のあと http://localhost:8000/ を開く（`file://` では画像を読めない）
- 先に `README.md` を読む。ゲームの仕組み、操作、3 コースの説明、確認用のスクリプトが書いてある

## ゲームについて知っておくこと

- 80 年代アーケードの「スプライトの拡大縮小・回転で 3D に見せる」技法を使ったオリジナル作品。**特定の既存ゲームの再現ではない**。動画のタイトル・概要欄・字幕で、既存ゲームの名前やメーカー名を使わない（「80 年代アーケード風」などの言い方はよい）
- 画面に出る物体は、すべて画像を `setTransform`（拡大縮小＋回転）して `drawImage` で描いている。ポリゴンは使っていない
- 絵は OpenAI GPT Image で生成した。原画とプロンプトは `assets/raw/`（`*.png` と `*.json`）、ゲーム用に加工した画像は `assets/`
- 描画の解像度は 960×540 固定（`game.js` の `W`, `H`）。ゲームの進行は 1/120 秒刻み
- 3 コース

| 番号 | 名前 | 全長 | 見どころ（`s` はスタートからの距離 m。1 周するとコースの全長ぶん増える） |
|---|---|---|---|
| 1 | MEADOW LOOP（青空と田園） | 3247m | 丘のジャンプ s≈1270、最高地点 58m s≈810、立体交差：上の道 s≈1876（高さ 45m）が下の道 s≈194（19m）の上を越える |
| 2 | CANYON RIDGE（夕焼けの峡谷） | 2541m | 大きな落差のジャンプ s≈1040（最高地点 60m）、最もきついカーブ s≈1534 |
| 3 | TWILIGHT BAY（夕暮れの海） | 2705m | ジャンプ s≈1668、左へ 270 度回り込む立体交差：上の道 s≈1466（50m）が下の道 s≈190（10m）の上を越える |

### 確認用の仕掛け（そのまま撮影に使える）

`game.js` に、テスト用の入口がある。

| 入口 | 内容 |
|---|---|
| `?autopilot` | プレイヤーの車を自動運転にして、すぐカウントダウンから始める |
| `?course=2` | コース 2 で始める（1〜3） |
| `window.__game` | 状態。`state`（`title` / `countdown` / `race` / `finish`）、`cars`、`player`、`raceTime` など |
| `window.__setCourse(i)` | コースを切り替えてレースを最初からにする（i は 0〜2） |
| `window.__advance(秒)` | ゲームを指定した秒数だけ進める（描画はしない） |
| `window.__freeze = true` | 実時間でゲームが進むのを止める。描画（requestAnimationFrame）は続く |
| `window.__fall()` | プレイヤーの車をコースアウトさせる |
| `window.__roadY(car)` | その車がいる地点の路面の高さ |

車の状態：`s`（距離）、`lat`（横位置。-1〜1）、`v`（速さ m/s）、`y`（高さ）、`fall`（落下中の情報。`fall.landed` が true なら地面に着いた）、`blink`（復帰後に点滅している残り秒数）。

`tools/check.mjs` が、Playwright でこれらを使って 3 コースを走らせ、スクリーンショットを撮るお手本になっている。

## 撮影のしかた（おすすめ）

実時間の画面録画ではなく、**1 コマずつ進めて保存する**。速いマシンでも遅いマシンでも同じ映像になり、コマ落ちもしない。

1. Playwright（Chromium）でページを開き、`window.__freeze = true` にする
2. 1 コマごとに `window.__advance(1 / 60)` で進め、`requestAnimationFrame` を 2 回待って描画させてから、`canvas` を PNG で保存する（`canvas.toDataURL('image/png')` か、canvas 要素のスクリーンショット）
3. 連番 PNG を ffmpeg で 60fps の動画にする
4. 乱数を使っている（敵の速さ・ミス、画面の揺れ）。撮り直しても同じ映像にしたいときは、`page.addInitScript` でページ読み込み前に `Math.random` を、シード付きの乱数（mulberry32 など）に置き換える
5. 狙った場面は、車の `s` や `lat` を直接書き換えて作れる。書き換えたら `y = window.__roadY(car)`、`vy = 0`、`air = false` もそろえる。敵の車を周りに並べると見栄えがよい

### 縦画面への対応（どちらかを選ぶ）

- **A（おすすめ）縦長で描画するモードを足す**：`?portrait` などで `W=1080`、`H=1920` にし、焦点距離（`FOCAL`）と HUD の位置・大きさを縦長に合わせる。空と地面を描く `drawBackdrop` の `R` は、回転しても画面を覆う半径なので、`Math.hypot(W, H) / 2` 以上にする。ゲームとしての通常表示（16:9）は壊さないこと
- **B 16:9 の映像を縦の枠に置く**：1920×1080 で撮り、縦画面の中央に置く。上下はタイトル文字やぼかした背景で埋める。作るのは簡単だが、映像が小さくなる

どちらでも、YouTube ショートの画面では、下の約 25% と右側の約 15% にボタンや説明文が重なる。字幕や HUD（速度表示など）はその範囲を避ける。

### 音

ブラウザの音（WebAudio で合成したエンジン音・効果音）は、1 コマずつの撮影では録れない。次のどちらかで作る。

- **エンジン音をあとから合成する**：撮影中に、コマごとに `player.v` とできごと（カウントダウン、ゴール、コースアウトの着地など）を記録しておく。それを使って、Python（numpy）でゲームと同じ式から音を作る。ゲームの式は `game.js` の `updateAudio`、`beep`、`crashSound` にある
  - エンジン：`gear = min(5, floor(v / 18))`、`rpm = (v - gear * 18) / 18`、`f = 55 + gear * 9 + rpm * 70`。のこぎり波 f と矩形波 f/2（音量 0.4）を混ぜ、900Hz のローパスに通す
  - カウントダウン 440Hz（0.2 秒）×3 → GO 880Hz（0.6 秒）。周回 760Hz。ゴール 660Hz → 990Hz。コースアウトの着地はノイズ（700Hz ローパス、0.5 秒）＋ 70Hz。復帰 520Hz → 780Hz
- **BGM を足す**：ユーザーが用意した、または利用条件を確認したフリー素材だけを使う。使う前に、どの曲を使うかユーザーに確認する

## 進め方

1. README と `game.js` を読み、`?autopilot` でゲームが動くことを確かめる
2. 縦画面への対応（A か B）と、音の作り方をユーザーに確認する
3. 撮影スクリプトを作る（例：`video/record.mjs`）。場面ごとに連番 PNG を書き出す
4. 編集スクリプトを作る（例：`video/build.py` か ffmpeg のコマンド）。場面をつなぎ、字幕と音を重ねる
5. できた動画を確かめる
   - `ffprobe` で解像度・fps・長さ・音声トラックを確認する
   - 数秒おきにコマを書き出して目で見て、字幕が切れていないか、安全な範囲に入っているか、場面のつなぎ目が不自然でないかを確認する
6. サムネイルと、タイトル・概要欄・ハッシュタグの案を作る

## 守ること

- 動画や連番 PNG は大きいので、git に入れない。`video/out/` と `video/frames/` を `.gitignore` に追加する
- ゲームに縦画面モードなどを足すときは、通常の 16:9 の表示と既存の確認スクリプト（`node tools/check.mjs <出力フォルダ>`）が引き続き動くことを確かめる
- 必要なもの：Node.js と Playwright（`npm i -D playwright` → `npx playwright install chromium`）、ffmpeg、Python 3（numpy、Pillow）
- 字幕や概要欄で、既存のゲームや会社の名前・ロゴを使わない
